# Qobuz-Only Music App — Feature Checklist

This document tracks the requested product scope against the current iOS implementation. It is an implementation audit, not a claim that live Qobuz endpoints have been verified end to end.

## Status key

- **Implemented** — the core behavior is present in the current code.
- **Partial** — some meaningful behavior exists, but the full product requirement is not met or is not verified.
- **Not implemented** — no supporting implementation was found in the current source tree.

## Feature status

| Status | Feature | Current implementation / remaining work |
|---|---|---|
| **Implemented** | Make Qobuz the app’s sole music source | The app’s catalog and playback paths are Qobuz-backed. The local track/library models, indexing/import store, document picker, fixture-backed library screens, and queue-only local fallback have been removed. Settings no longer exposes local import. Default tabs are Discover, Search, Albums, Artists, and Tracks; Tracks now means saved Qobuz tracks, not local files. Versioned preference migration removes unsupported `playlists` and `genres` IDs, introduces Tracks for existing users, and preserves deliberately hidden tabs on subsequent saves. The tab strip scrolls horizontally when five tabs cannot fit on a narrow screen. |
| **Implemented** | Qobuz discovery page | `QobuzCatalogViewController` uses `discover/index` for New Releases, Qobuzissims, Ideal Discography, Album of the Week, Most Streamed, Press Awards, and derived artist links. `genre/list` powers genre filters; playlist tags and `discover/playlists` provide genre/tag filtering and offset pagination. Selecting a playlist loads its tracks and supports play/shuffle. Live Qobuz endpoint behavior still needs verification. |
| **Partial** | Search Qobuz | Search calls Qobuz album, artist, and track endpoints and renders grouped results. Search runs on submit; debouncing, pagination, richer filters, and resilient handling of partial endpoint failures need follow-up. There is also a separate, short-lived track-search cache, but that is not audio caching. |
| **Implemented** | Restore the pre-Qobuz library presentation and interactions | Saved Albums use the historical two-column artwork grid; Tracks and Artists use 78-point custom rows with 54-point artwork and circular artist portraits. Pull down at the top to reveal local search, All/A–Z/Z–A sorting, and Refresh; swipe upward to hide the tools without clearing the filter/sort. Track swipes restore enqueue/play-next/local-like/more actions, track long press opens album/artist navigation, and album long press opens the queue menu. Inward content-edge swipes navigate tabs and reach Settings after the last enabled tab, including while signed out. Settings retains its own edge-swipe return. Existing player/queue composition and player-to-queue wiring are retained. This is a presentation adaptation, not a backend rollback. |
| **Implemented** | Browse saved Qobuz albums | The Albums tab shows albums added to the signed-in user’s Qobuz library, loaded through `favorite/getUserFavorites`, rather than editorial new releases. Library loading follows pagination metadata and deduplicates results; stalled/repeated pages fail instead of silently returning a truncated library. Local search/sort, the revealed Refresh button, and returning to the tab retain the working saved-library behavior; refresh failures preserve previously loaded content. Live favorites pagination still needs verification. |
| **Partial** | Album pages and details | Album selection fetches album metadata and tracks; the detail view supports track selection, play, shuffle, and queue actions. The cover now loads asynchronously from the album artwork URL instead of depending on a previously cached playback image. Album-header artist navigation uses the primary album artist, while track artist navigation retains the performer’s ID. Add/remove album-library actions now use authenticated Qobuz favorites mutations, confirmed-success state, pending/error feedback, and saved-Album refresh. Downloads remain unsupported; live album/artwork/favorites behavior still needs verification. |
| **Implemented** | Browse saved Qobuz artists | The Artists tab loads artists saved in the user’s Qobuz library through `favorite/getUserFavorites`, not artists derived from editorial releases. It supports local saved-artist filtering and library refresh. Unknown release counts display “Artist on Qobuz” rather than misleadingly showing “0 albums.” |
| **Implemented** | Browse and play saved Qobuz tracks | The Tracks tab loads saved tracks from `favorite/getUserFavorites`, including paginated results, and routes selection through the shared Qobuz player. Search filters saved tracks by title, artist, and album. Selecting a track queues it and all subsequent tracks in the displayed filtered/sorted order, excluding preceding/nonmatching tracks. Library-row artwork loads as rows become visible rather than fetching every image in a large library at once. |
| **Implemented** | Artist profiles, releases, and top tracks | Artist detail uses `artist/page` for biography, portrait metadata, and top tracks. Separate paginated `artist/getReleasesList` calls load albums, EPs/singles, live releases, and compilations. The profile displays release cards and playable top tracks with playback, navigation, and swipe actions. Partial release failures retain successfully loaded releases, biography, portrait, and top tracks, with a “Releases incomplete” warning. Live profile/release behavior still needs verification. |
| **Implemented** | Detail-screen artwork loading | Album covers, artist portraits, and release-card artwork are fetched asynchronously through the artwork pipeline using size-specific cache keys and stale-response guards. Portrait URLs can be constructed from Qobuz’s `hash`/`format` metadata. Missing/failed artwork keeps the placeholder; live image delivery remains unverified. |
| **Implemented** | Qobuz account sign-in and sign-out | OAuth sign-in is presented in an authentication session; credentials are stored in Keychain on device (simulator may be session-only), and sign-out removes them. Unauthenticated catalog tabs launch sign-in directly without routing through Settings; OAuth starts automatically, then the sign-in screen closes and the user returns to the tab they started from. Player configuration discovery is shared across sign-in and playback, checks HTTP responses, and shows sanitized response diagnostics on failure. The implementation does not show richer account/subscription management. Live sign-in is not covered by the checked-in unit tests. |
| **Partial** | Account and audio-quality settings | Settings exposes and independently persists MP3, CD, Hi-Res 96, and Hi-Res 192 choices, refreshing account/quality state on return. Guidance distinguishes requested quality, next-stream timing, subscription/track availability, and device-route limitations. Account sign-in has dismissal and retry controls. Stream requests use the selected format and the player reports returned metadata. Rich account/subscription management, actual device output/resampling, and lossless fidelity remain unverified. |
| **Implemented** | Shared in-app player for Qobuz playback | Catalog track/album playback uses a common queue controller and `QobuzStreamPlayer`; the mini-player, full player, and queue view control the same playback state. Queue and player behavior is integrated in the app. This does not imply lock-screen/Control Center controls or persistent playback restoration. |
| **Partial** | Queue playback and queue actions | Qobuz queues support play, pause, seek, next/previous, enqueue, and play-next flows. Metadata-only album cards resolve tracks before executing the requested enqueue/play-next action. Long queues register metadata without eagerly downloading every cover: player artwork loads for the current track, and Queue loads header/visible-row artwork with size-specific caching and stale-response guards. Artwork completions do not require queue ID/index changes, and playback ticks do not reset queue scroll/swipe state. Authenticated startup now restores the persisted queue/index/elapsed position paused, hydrating presentation metadata without collapsing duplicate entries. Positional selection/removal/reordering and an Edit/Done control are wired; clear/shuffle upcoming preserve the current stream and elapsed time. Regression coverage checks duplicate occurrences, stale stream resolutions, and paused restoration. Live restoration/streaming and device timing remain unverified. |
| **Partial** | Lossless and Hi-Res playback | The app offers Qobuz CD/Hi-Res stream formats and sends the selected format ID when resolving a stream. This is a format-selection path, not proof of bit-perfect output; device route constraints, actual decoded stream quality, and lossless acceptance testing remain. |
| **Not implemented** | Gapless playback | Playback uses a single `AVPlayer` item. At track end it stops the current item, advances the queue, resolves the next URL, and creates another player item. There is no gapless queue/preparation or cross-track continuity implementation. |
| **Not implemented** | Proactively prefetch/cache upcoming queue audio | No audio download/prefetch pipeline or upcoming-track stream cache was found. The existing Qobuz search cache holds track metadata briefly; artwork caches are image-only and do not cache playable audio. |
| **Partial** | Add/remove items in the Qobuz library | Album detail now calls `favorite/create` and `favorite/delete` with `album_ids`, updating state only after confirmed success and refreshing saved Albums. Track and artist mutations remain unimplemented. Existing likes remain app-local and are not synchronized to Qobuz favorites. Live mutations remain unverified. |
| **Not implemented** | Automatic downloads for items added to the library | No automatic-download preference, library-add trigger, or download manager was found. Reading existing Qobuz favorites does not download audio; local likes do not trigger downloads either. |
| **Not implemented** | Manual track/album downloads | No audio download task, persistent downloaded-file index, download UI, or offline playback path was found. |
| **Not implemented** | Offline-ready library/download management | The legacy local-file library has been removed. Qobuz tracks are not stored as managed offline downloads; a Qobuz-specific downloaded library and its storage controls still need to be built. |

## Suggested completion order

1. **Add Qobuz library mutations:** the library source of truth is now Qobuz favorites, and reading saved albums/artists/tracks is implemented. Add `favorite/create`/`favorite/delete` actions and synchronize their state; decide whether existing app-local likes should remain separate or become Qobuz favorites.
2. **Build one download subsystem:** persistent download records, storage location, progress/errors/retries, cancellation/deletion, and offline playback. Add manual download actions first, then the automatic-download preference/trigger.
3. **Add queue prefetch:** resolve and cache the next eligible queue item(s), with limits, quality-aware cache keys, cancellation on queue changes, and cellular/storage policy.
4. **Implement gapless transitions:** prepare the next playable item before the current item ends and test consecutive album tracks, buffering, skips, queue edits, and stream-resolution failures.
5. **Complete remaining catalog browsing:** improve global search pagination, filters, and partial-failure handling; add broader catalog browsing if in scope. Saved-library albums/artists/tracks, Discover editorial sections, and genre/tag-filtered playlist pagination are implemented; verify them against live Qobuz responses.
6. **Verify playback quality on devices:** test available Qobuz formats against actual stream metadata and device/audio-route behavior; clearly distinguish requested from delivered quality.
7. **Add automated coverage:** test download lifecycle, persistence/offline playback, automatic-download triggers, prefetch cancellation, and gapless transitions; keep live-Qobuz tests separately configurable.

## Audit notes

- Evidence comes from the current Swift source and checked-in tests, using `QOBUZ_API_CHEATSHEET.md` and Qobine as API references. Relevant implementation areas include `ios/Music/Sources/Data/QobuzStreamingClient.swift`, `QobuzCatalogModels.swift`, `QobuzCatalogMapper.swift`, `Models.swift`, `PlaybackController.swift`, `QobuzStreamPlayer.swift`, `QobuzPreferences.swift`, `ios/Music/Sources/UI/Screens/QobuzCatalogViewController.swift`, `DetailViewControllers.swift`, `ScreenModels.swift`, `QobuzAccountViewController.swift`, `ios/Music/Sources/UI/Components/TabStripView.swift`, and `ios/Music/Sources/RootViewController.swift`.
- Checked-in tests cover authenticated favorites requests with mocked responses, pagination/stalled-page handling, saved-library filtering and track selection, artist release categories and partial failures, portrait/top-track decoding, performer IDs, tab-preference migration, and artwork/cache/layout behavior at 320- and 375-point widths, alongside existing playback tests. They do not establish that live authentication/catalog/artwork requests work or validate download, lossless, or gapless behavior. The catalog client preserves the failing endpoint and a bounded JSON error message for catalog HTTP failures to aid diagnosis.
- During the earlier library/detail implementation, the simulator build and all 44 unit tests passed, as did the default-tabs UI test. The then-existing Settings UI test incorrectly expected “Continue with Qobuz” to open Settings rather than sign-in. The restoration corrects that test to use the content-edge Settings gesture.
- After the presentation restoration, the Debug simulator build, all **57 unit tests**, and all **4 UI tests** passed on a disposable iPhone SE (3rd generation), iOS 26.5 simulator. Regression coverage includes filtered/sorted queue suffixes, custom row/grid geometry, callback routing and long-press handling, edge thresholds, visible-only Queue artwork, stale/reused artwork completions, metadata updates without queue reloads, and injected player-to-queue positional selection. UI tests inject actual edge drags for signed-out Settings access/return, verify tab editing leaves Settings visible, and exercise appearance/quality controls without OAuth. `git diff --check` passed for the changed source/tests/checklist.
- Current state: on a clean iOS 26.5 simulator the full suite passes — **219 tests, 0 failures**, with the opt-in demo/snapshot suites skipped unless their environment variables are set. A fresh clone builds with `xcodegen generate` plus `xcodebuild`.
- Retained XCTest visual captures were inspected for the restored album grid, track/artist rows, player, and Queue at 320×568 and 375×667. They use synthetic/mocked content, not live library artwork. Signed-in native row swipes/long presses/pull-to-reveal, album-resolution queue actions against Qobuz, live authentication, streaming, and real artwork delivery still require account/device smoke testing; the automated gesture-handler/callback checks are not a claim of end-to-end live verification.
- `xcodegen generate` previously failed on missing root resources `THIRD_PARTY_NOTICES.md` and `QOBINE_GPL-3.0.txt`. Both now exist, so the project can be regenerated from `project.yml`; the generated Xcode project builds cleanly from a fresh clone.
- The stream client identifies its signing/streaming protocol as ported from Qobine under GPL-3.0. The repository now ships `LICENSE` (GPL-3.0), `THIRD_PARTY_NOTICES.md`, and `QOBINE_GPL-3.0.txt`, and bundles the notices into the app resources.
